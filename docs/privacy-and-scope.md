# Privacy and supported scope

AccessLab has no accounts, server, telemetry, remote scan, AI service or automatic report persistence. Code, axe rules, matrices and docs are packaged locally. The only persistent application data is validated dock/target-threshold/blur preferences in chrome.storage.local. Reports, selected regions, target references and actual focus visits stay in document memory and are cleared by Reset/Close/reload. Inspection never records input values or intercepts typing. Full local source is reviewable.

Export requires explicit action. It omits URL user information/query/fragment, title, page text/HTML snippets, input values, cookies, tokens and screenshots as collected fields. Pathnames and descriptive locators may still expose identifiers/page structure, potentially sensitive in context; preview and redact locally before sharing. Markdown untrusted punctuation is entity-encoded; JSON should be displayed as text. The 5 MiB budget refuses oversized output rather than silently dropping findings. Help links open official Deque guidance only when chosen; following an external link is a user navigation, not a report upload.

Production permissions: activeTab, scripting, storage. No broad host permissions, tabs/debugger/downloads permission, static all-site content script, backend or remote executable code. Browser-provided activeTab access follows explicit toolbar action. Privileged/internal/file/store pages fail intentionally. Production native-action tests run in their own debugging-enabled test browser; that flag is not shipped or enabled in a user's Chrome by this project.

Coverage is the top document and accessible open shadow roots; frames and closed shadows remain outside supported audit/inspection coverage. Closed internals cannot be counted comprehensively. Mutation tracking covers shadows discoverable at activation or through observed insertions; a shadow attached later without observable light-DOM insertion may require manual rerun. Native modal top-layer content may cover the panel. Styles/policies/host changes can prevent injection or safe previews and should produce explicit failures. Hard reload is recovery after development hot reload/uninstall leaves temporary resources.

Audit preflight limits: 5,000 elements / 1,000 interactive elements including discoverable open shadows. Larger audits are refused because engine startup can synchronously block the page. Target inspection measures up to 1,000 candidates, discloses omitted candidates, shows at most 200 outlines; focus keeps at most 100 connected visits; findings display pages of 50 but export all within budget. Preview regions allow at most 500 elements and exclude html/body, fixed/sticky/absolute layout, inline-important host filters and unavailable custom internals.

Target boxes need spacing/exception/context review, focus trail is actual observed visits rather than complete predicted order, and axe findings/needsReview do not prove WCAG conformance. Machado full-severity color matrices, grayscale and blur are rendering approximations with gamut/individual-perception limits; they do not authentically simulate disability. Actual Chrome zoom, screen-reader output and usability with disabled participants require separate human evidence. See docs/release-checklist.md and docs/reliability.md.
